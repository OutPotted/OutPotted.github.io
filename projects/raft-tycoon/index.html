01

Authoritative construction & upgrades

Design approach

A construction service could validate plot ownership, prerequisites, and a server-defined price before accepting an upgrade. The logical purchase and unlock should share one controlled state transition.

Validation plan

Try buying twice, using another player’s plot, bypassing prerequisites, and purchasing with an insufficient balance.

02

Production & currency accounting

Design approach

A possible economy separates production definitions from balance mutations. Timed accrual can be calculated from validated server state, with capped catch-up rules and a single transaction entry point.

Validation plan

Test rate changes, very large balances, invalid numerical input, repeated rewards, and changes made while a production cycle is running.

03

Rebirth & persistent progression

Design approach

A rebirth flow can define exactly which fields reset and which remain. A versioned profile can store unlocks, progression, and economy state with explicit handling of storage errors.

Validation plan

Check that rebirth is accepted only from a valid state and that resets cannot grant a reward twice. Test reconnecting around the reset boundary.

04

Plot lifecycle & multiplayer cleanup

Design approach

A plot lifecycle could own its objects, timers, and event subscriptions. Releasing a plot should clean up those resources before another player receives it.

Validation plan

Repeatedly join, leave, claim, and release plots; monitor for orphaned objects, timers, and references.
